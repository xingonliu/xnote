# XNote Agent 记忆与上下文架构

> 文档版本：v1.0
>
> 文档状态：已确认方案，后续实现以本文为准
>
> 适用平台：Android 13（API 33）及以上的手机、平板
>
> 关联文档：[XNote 功能清单与页面组成](./XNote%20功能清单与页面组成.md)、[XNote 开发顺序](./XNote%20开发顺序.md)、[XNote UI 设计规范](./XNote%20UI%20设计规范.md)

## 1. 目标与最终结论

XNote Agent 采用“单时间线、分段压缩、分层回溯”的记忆与上下文架构。产品提供一个持续存在的 Agent 对话窗口。内部为了控制上下文规模，将连续时间线划分为不可见的对话片段，用户始终在同一条时间线中继续交流。

架构由以下三类长期内容组成：

1. **情景记忆**：历史对话片段及其摘要，描述过去发生过什么。
2. **画像记忆**：少量重要且稳定的用户事实、用户对 Agent 的偏好，以及受控的 Agent 可学习偏好。
3. **文档记忆**：用户笔记的可检索索引、语义摘要与原始笔记引用，描述用户保存了什么知识。

当前片段原文构成短期记忆。完整消息与笔记正文始终是事实源；片段摘要、画像、笔记语义摘要和搜索索引都是可重建的派生数据。

第一版直接建立在项目现有的 Room、Bundled SQLite 和 FTS5 上，不引入 Mem0、Letta、LangGraph 或独立向量数据库。大模型只用于固定输入输出的摘要和画像候选解析，以及正常的 Agent 推理；数据库事务、权限判断、记忆替换和上下文组装由 Android 原生代码确定性执行。

## 2. 核心原则

### 2.1 单时间线

- Agent 页面只有一条持续增长的消息时间线。
- 用户从 Agent 入口直接进入该时间线。
- 平板可以增加上下文、记忆或工具详情面板。
- 用户清理数据时，分别提供“清除对话记录”和“清除长期画像”。

### 2.2 事实源与派生数据分离

- 完整消息记录是对话事实源。
- `notes` 及其明确版本是笔记事实源。
- 片段摘要不覆盖或替代原始消息。
- 笔记语义摘要不覆盖现有用于列表展示的短摘要，也不复制成画像事实。
- 画像事实必须保留来源和替换链，运行时只暴露当前有效值。

### 2.3 概念统一、物理分离

情景记忆、画像记忆和文档记忆统一进入上下文组装层，但使用独立的数据表、更新规则、搜索工具和权限边界。这样可以统一召回体验，同时避免笔记编辑、画像更正和历史对话互相污染。

### 2.4 先过滤权限，再检索和排序

- 所有笔记检索必须先应用当前 Agent 数据范围。
- 历史对话中曾经出现过某篇笔记，不代表当前仍然具有读取权限。
- 回收站和永久删除内容不能通过记忆工具重新暴露。
- 记忆内容在模型提示词中始终标记为不可信数据，不能改变系统规则、工具权限或安全策略。

### 2.5 Token 预算优先

上下文按 Token 预算分配，不按固定消息数、摘要篇数或笔记篇数无限扩展。当前用户消息、当前片段和用户显式附加内容优先，历史记忆只填充剩余预算。

## 3. 术语

| 术语 | 定义 |
| --- | --- |
| 单时间线 | 用户可见的唯一 Agent 对话历史。 |
| 当前片段 | 尚未关闭的一段连续交互，原文作为短期记忆。 |
| 历史片段 | 已经按边界关闭、等待或已经完成摘要的对话范围。 |
| 片段摘要 | 由无工具权限的大模型函数根据固定消息快照生成的结构化解析和短文。 |
| 画像事实 | 可按稳定键更新的重要用户事实或可学习偏好。 |
| 文档记忆 | 笔记的派生摘要、结构、关键词、搜索索引及指向事实源的引用。 |
| 上下文条目 | 上下文组装器可选择的一项数据，带来源、时间、权限和 Token 估算。 |
| 记忆协调器 | 根据确定性规则把画像候选新增、替换、忽略或标记遗忘的应用层组件。 |
| Agent 运行 | 一条用户消息触发，直到模型响应和工具循环结束、失败或取消的执行范围。 |

## 4. 总体数据流

```text
用户消息与 Agent 运行
        │
        ├─ 追加完整消息记录 ────────────────┐
        │                                  │
        ├─ 当前片段原文 → 短期记忆          │ 事实源
        │                                  │
        └─ 片段关闭                         │
             ├─ 片段摘要函数 ──→ 情景记忆  │
             │                    │         │
             │                    └─ 画像候选
             │                          │
             │                    记忆协调器 → 画像记忆
             │
             └─ 笔记引用 ───────────────→ notes / note_memory_index

新一轮上下文组装
├─ 系统规则与权限
├─ 受控的 Agent 固定画像
├─ 当前有效用户画像
├─ 当前片段原文
├─ 用户显式附加的笔记或文件
├─ 相关文档记忆
├─ 相关历史片段摘要
└─ 少量近期片段摘要
```

## 5. 完整对话记录

### 5.1 保存范围

完整记录按时间线追加，不通过重写整段 JSON 保存。需要覆盖：

- 用户文字消息。
- Agent 可见回复。
- 图片、文件和笔记卡片的引用及展示元数据。
- Tool Call 名称、参数摘要、状态和受限结果摘要。
- 权限请求及用户决策。
- 错误、取消和恢复事件。
- 模型、提示词和 Agent 配置版本。

流式回复先以 `streaming` 状态创建，完成后转为 `completed`；用户停止、超时或异常分别记录 `cancelled`、`timed_out` 或 `failed`。崩溃恢复时，遗留的 `streaming` 记录必须转为可识别的中断状态，不能当作完整 Agent 回复参与摘要。

### 5.2 不直接保存的内容

- 图片和文件二进制不写入消息表，只保存附件引用。
- API Key、认证令牌和敏感工具参数不进入可搜索文本。
- 大型 Tool Call 返回值不复制到消息正文，只保存受限摘要和事实源引用。
- 笔记全文不复制进历史 Tool Call 结果；保存笔记 ID、内容版本和必要的命中片段。

### 5.3 顺序与一致性

- 每条消息具有全局递增的时间线顺序值，避免仅依赖毫秒时间排序。
- 一次 Agent 运行中的消息、工具调用和结果通过 `runId` 关联。
- 所有可参与摘要的记录必须具有最终状态。
- 关闭片段、确定消息范围和创建摘要任务在同一数据库事务中完成。

## 6. 对话片段

### 6.1 片段的内部语义

片段只用于内部压缩、召回、权限到期和故障恢复。主界面不展示独立片段列表，也不为片段提供名称或管理操作。时间线可以使用日期或自然时间分隔。

### 6.2 关闭条件

满足任一条件时可以关闭当前片段：

1. 新用户消息到来时，距离上一次已完成交互达到或超过 30 分钟。
2. 当前片段原文超过配置的最大 Token 或消息容量。
3. 用户明确表示开始新话题。
4. 后续有可靠的话题切换检测时，由确定性阈值建议切分；第一版不依赖模型自动切题。

30 分钟从上一次完成的用户可见交互计算，不从正在执行的 Agent Loop 中途计算。Agent 仍在运行、工具仍在执行或等待权限确认时，不得因为时间经过而拆分片段。

片段容量必须可配置，并在第一版模型确定后按其上下文窗口设置。时间边界是主要规则，容量边界是防止高频长对话形成超大片段的硬保护。

### 6.3 Android 调度规则

Android 后台任务不保证在第 30 分钟精确运行，因此不能把计时器触发作为唯一正确性来源：

- 新消息到来时先检查间隔，原子关闭旧片段并创建新片段。
- App 在前台进入空闲状态时可以提前提交摘要任务。
- WorkManager 负责尽力执行已关闭片段的摘要任务，但不承诺精确时间。
- 应用启动时补扫所有已关闭但未摘要、失败后可重试或状态悬空的片段。
- 同一个片段的摘要任务使用唯一键，重复调度不得生成重复摘要。

### 6.4 摘要尚未就绪

新片段开始时，前一片段的摘要可能尚未完成。此时不能阻塞用户发送消息：

- 优先使用已有摘要。
- 没有摘要时，在剩余 Token 预算内带入前一片段的有限原文尾部。
- 原文尾部仍过长时做确定性裁剪，并标注“前一片段摘要待生成”。
- 摘要完成后，后续运行改用摘要，不回写或重放已经完成的模型调用。

## 7. 片段摘要函数

### 7.1 执行边界

片段摘要由 Agent 以外的独立大模型函数执行：

- 没有笔记、文件、网络、Shell、MCP 或其他 Agent 工具权限。
- 输入是已经固定的片段消息快照和固定版本的解析提示词。
- 不读取片段范围以外的聊天记录。
- 不直接更新画像，不执行工具，不修改笔记。
- 输出必须通过结构化 Schema 校验。

### 7.2 输出内容

摘要同时保存便于模型阅读的短文和便于程序处理的结构化结果。推荐结构：

```json
{
  "title": "讨论旅行计划与预算",
  "summary": "用户准备十月旅行，决定优先选择高铁并继续比较酒店预算。",
  "topics": ["旅行", "预算"],
  "decisions": ["城市间优先选择高铁"],
  "openLoops": ["尚未确定酒店"],
  "userFactCandidates": [],
  "agentCommitments": ["下次继续比较酒店"],
  "referencedNotes": [
    {
      "noteId": "note-id",
      "contentVersion": "content-version",
      "relation": "讨论"
    }
  ],
  "keywords": ["十月", "高铁", "酒店"],
  "sourceMessageStartId": "message-start",
  "sourceMessageEndId": "message-end"
}
```

解析提示词必须要求：

- 只总结消息中明确存在的事实。
- 区分用户陈述、Agent 建议和最终决定。
- 不把 Agent 自己生成的内容当作用户画像事实。
- 不把工具结果中的笔记正文复制进摘要。
- 无法确认的信息保持缺失，不补全或推断。
- 保留仍未完成的承诺、问题和下一步。

### 7.3 大小与版本

- 摘要短文按 Token 上限生成，不能使用无界长度。
- 保存 `modelProvider`、`modelId`、`promptVersion`、`sourceHash` 和生成时间。
- 同一 `sourceHash + promptVersion + modelId` 的结果必须幂等。
- 提示词或模型升级时可以排队重建旧摘要，但不能阻塞当前对话。
- Schema 校验失败、内容为空或来源范围不一致时，任务失败并保留原始消息，不能写入部分有效摘要。

## 8. 画像记忆

### 8.1 保存范围

长期画像只保存对未来多次交互持续有价值的重要信息：

- 用户明确陈述的稳定个人偏好。
- 用户明确要求 Agent 记住的信息。
- 用户对回复长度、语言、格式和工作方式的长期偏好。
- 经过多次一致行为支持、但必须标为推断且置信度较低的偏好。
- 受控的 Agent 可学习回答偏好。

以下内容不进入画像：

- 一次性问题和临时任务参数。
- 整篇笔记或大段笔记正文。
- Agent 自己猜测的身份信息。
- 系统规则、工具权限、安全策略和应用能力声明。
- API Key、密码、令牌等秘密。

### 8.2 原子事实与活动视图

画像按稳定键保存原子事实，而不是让模型持续重写一个无限增长的大 JSON。例如：

```text
user.response.language = zh-CN
user.response.detail = concise
user.location.current = 上海
agent.response.tone = calm
```

运行时只把每个键当前有效的值组装成画像。数据库保留旧值、有效期和替换链：

```text
旧值：user.location.current = 北京
validTo = 新事实生效时间

新值：user.location.current = 上海
active = true
supersedesId = 旧事实 ID
```

新的有效值在上下文中替换旧值，但不物理覆盖历史记录。

### 8.3 事实优先级

发生冲突时使用固定优先级：

```text
用户明确纠正
> 用户明确陈述
> 多次一致行为
> 模型推断
```

- 较低级来源不能覆盖较高级来源。
- 同级明确陈述通常以更新且具有清晰时间语义的事实为准。
- 状态事实可以替换，例如当前居住地；历史事件不能因为相似而互相覆盖。
- Agent 回复永远不能成为用户事实的唯一来源。

### 8.4 记忆协调器

片段摘要函数只输出画像候选。应用层记忆协调器读取候选、现有活动事实和来源元数据，执行：

- `ADD`：不存在同键事实，新增。
- `SUPERSEDE`：新事实按优先级和时间规则替换活动值。
- `IGNORE`：重复、低价值、低置信度或无法确认。
- `FLAG_FOR_REVIEW`：高敏感、冲突不清或可能误判，等待用户确认。

协调结果必须可审计，不能由自由文本模型输出直接决定数据库删除或覆盖。

### 8.5 Agent 画像边界

Agent 相关信息拆成三层：

1. **固定 Agent 配置**：名称、身份、基础人格和产品定义，由用户设置或应用版本控制。
2. **Agent 可学习偏好**：用户希望 Agent 如何表达、组织答案或配合工作，可以进入画像记忆。
3. **不可学习规则**：系统提示词中的安全规则、工具权限、数据范围和能力边界，任何聊天或记忆都不能修改。

普通聊天不得自动改写 Agent 身份和不可学习规则。

### 8.6 用户控制与遗忘

- 用户可以查看每条活动画像、来源、更新时间和是否为推断。
- 用户可以更正、删除或禁止再次记住某个键。
- 删除画像但保留原始聊天时，必须写入遗忘标记，防止后台任务再次从旧聊天恢复同一事实。
- 用户后续明确提供同键新事实时，可以经确认解除遗忘标记。
- 清除全部对话和清除长期画像是两个独立操作，界面必须说明影响范围。
- 删除作为画像来源的消息后，应重新评估或撤销仅由该来源支持的派生事实。

## 9. 文档记忆

### 9.1 定位

笔记属于 Agent 的长期可检索知识，但笔记正文仍保存在笔记库，不复制进情景记忆或画像表。文档记忆保存的是派生索引和事实源引用。

项目现有 `Note.summary` 是把可见纯文本压缩为空白后截取最多 80 个字符的列表预览，不是大模型语义摘要。该字段继续只服务笔记列表；Agent 文档记忆使用独立数据结构。

### 9.2 派生索引

推荐的文档记忆索引至少包含：

```text
noteId
contentVersion / contentHash
title
notebookId
semanticSummary
outline
keywords
plainText
updatedAt
summaryStatus
summaryModel
summaryPromptVersion
```

- `noteId + contentVersion` 指向明确事实源。
- `plainText` 复用现有普通笔记与 Markdown 可见文本抽取。
- `semanticSummary` 与 UI 列表短摘要分开。
- 索引可删除、重建，不承担笔记版本事实源职责。

### 9.3 生成与失效

- 短笔记直接使用标题和正文，不必调用大模型生成语义摘要。
- 长笔记停止编辑一段时间后再排队生成摘要，不能在每次自动保存时调用模型。
- 使用 `contentHash` 去重，同一内容版本只生成一次。
- 笔记再次修改后立即把旧索引标为过期；摘要未更新时使用最新正文的 FTS 命中片段，不能把旧摘要标成当前事实。
- App 启动和后台任务补扫待处理或失败任务。
- 模型或提示词升级允许异步重建，不阻塞编辑。

### 9.4 进入上下文的三种方式

#### 用户显式附加

显式附加具有最高文档优先级，向上下文提供：

```text
[用户显式提供的笔记]
noteId: ...
contentVersion: ...
title: ...
updatedAt: ...
content: 完整正文或按预算选择的正文块
```

- 短笔记可以发送全文。
- 长笔记发送标题、语义摘要、结构和与当前请求相关的正文块。
- Agent 需要更多内容时调用 `read`。
- 附加行为为当前片段授予该版本的临时读取权限；片段关闭后不自动延续。

#### 自动相关性召回

上下文组装器可以在当前数据范围内对用户输入执行轻量笔记检索，只注入少量高相关的标题、摘要和命中片段。没有权限的笔记必须在检索前被排除，不能泄露标题、数量或相关度。

#### Agent 工具读取

`note_search` 返回匹配摘要，`read` 根据笔记 ID 和可选版本读取完整内容。工具调用时重新检查当前权限，不继承历史片段中曾有的权限。

### 9.5 媒体内容

- 表格中的可见文字进入纯文本索引。
- 图片、贴纸和画笔不自动作为原始媒体进入每次模型上下文。
- 第一版索引可以记录媒体类型、数量和用户填写的说明。
- 后续 OCR、图片描述或多模态摘要必须保存来源和生成版本，仍然属于派生数据。
- 只有用户显式附加且当前模型支持相应输入时，才发送原始图片或文件。

### 9.6 删除与版本

- 笔记进入回收站后立即退出自动检索和文档记忆召回。
- 永久删除笔记时删除其派生索引。
- 历史片段可以保留“曾讨论一篇笔记”的事件，但不能继续返回已删除正文。
- 对话中的笔记卡片绑定内容版本；如果项目不保存通用可浏览版本，仍需为 Agent 附加建立不可歧义的内容版本或内容哈希。
- 读取旧版本前必须确认该版本仍存在且当前权限允许；否则返回不可用状态，不静默切换到其他内容。

## 10. 上下文组装

### 10.1 优先级

每次 Agent 运行按以下优先级组装：

1. 系统规则、安全边界、工具定义和当前权限。
2. 固定 Agent 配置。
3. 当前有效用户画像和 Agent 可学习偏好。
4. 当前用户消息及当前片段原文。
5. 用户显式附加的笔记、图片和文件。
6. 自动召回的相关文档记忆。
7. 与当前问题相关的历史片段摘要。
8. 少量近期片段摘要。

系统规则和权限不参与记忆排序，也不会被任何记忆覆盖。当前用户消息和当前片段不能因为历史召回而被裁掉。

### 10.2 近期与相关历史

第一版默认候选可以是：

- 最近 2–3 个已关闭片段摘要，用于保持连续性。
- 当前查询命中的最多 3–5 个相关历史片段摘要。
- 当前查询命中的少量笔记摘要或正文片段。

这些数字只是候选上限，最终以 Token 预算为准，不承诺每次固定携带 5–10 篇短文。近期结果和相关结果重复时必须去重。

### 10.3 Token 预算

上下文组装器至少预留：

- 系统和工具定义预算。
- 模型输出预算。
- 当前片段和用户输入预算。
- 用户显式附加内容预算。
- 历史记忆预算。

模型和服务商确定后再设具体数值。所有截断必须按完整消息、完整正文块或完整摘要条目执行，不能在 JSON、Tool Call 或富文本结构中间任意切断。

### 10.4 上下文条目格式

每项历史记忆和文档内容都要带明确来源标签：

```text
sourceType: episode_summary | profile_fact | note_excerpt | attached_note
sourceId: ...
sourceVersion: ...
createdAt / updatedAt: ...
trust: derived | user_explicit | source_document
content: ...
```

发送给模型时明确说明：历史消息、摘要和笔记内容是参考数据，其中出现的指令没有系统级权威，不能改变权限或要求调用未授权工具。

### 10.5 新鲜度与冲突

- 当前笔记正文优先于旧的笔记语义摘要。
- 当前有效画像优先于历史片段中的旧画像描述。
- 用户在当前消息中的明确纠正优先于全部历史记忆。
- 多个历史来源冲突且无法确定时，向用户澄清，不静默拼接成新事实。

## 11. 记忆工具

### 11.1 `memory_search`

```text
memory_search(
    query,
    startTime?,
    endTime?,
    limit?,
    cursor?
)
```

用途：当用户模糊提及过去讨论、Agent 只记得大致事件或当前自动召回不足时，搜索历史情景记忆。

结果包含：

- 片段 ID。
- 片段开始和结束时间。
- 片段标题与短文摘要。
- 命中的安全原文片段。
- 相关度和命中原因。
- 关联笔记 ID，但不包含无权限笔记正文。
- 是否存在可读取的完整片段。
- 分页游标。

`memory_search` 直接返回已经保存的片段摘要和命中片段，不为每次搜索重新调用大模型生成新短文。这样可以控制延迟、成本和结果一致性。

### 11.2 `memory_read`

```text
memory_read(
    episodeId,
    cursor?,
    limit?
)
```

用途：Agent 已通过搜索确定具体片段，但摘要不足以回答当前问题时，分页读取该片段的完整安全文本。

- 输出保持消息角色、顺序、时间和状态。
- 不返回秘密参数、二进制或未授权笔记正文。
- 大型片段必须分页并限制单次输出大小。
- 每次读取都进入工具审计记录。

搜索和全文读取使用两个工具，不用 `fullText=true` 合并，以便分别限制权限、输出大小、调用次数和审计语义。

### 11.3 与笔记工具的关系

- `memory_search` / `memory_read` 搜索和读取过去的对话事件。
- `note_search` / `read` 搜索和读取当前笔记事实源。
- 情景记忆返回关联笔记 ID 后，Agent 必须调用 `read` 并重新通过当前数据范围检查。
- 内部上下文检索器可以统一排序来自情景记忆和文档记忆的候选，但 Agent 工具保持分离。

### 11.4 调用限制

- 记忆工具不是每轮必调用工具，只有自动上下文不足或用户明确回溯时才使用。
- Agent Loop 必须限制每次运行的搜索次数、读取次数和累计返回 Token。
- 重复相同参数且结果未变化的调用应被重复调用防护拦截。
- 搜索无结果时如实返回，不让模型虚构过去事件。

## 12. 检索策略

### 12.1 第一版

第一版使用本地 FTS5：

- 片段摘要 FTS：标题、短文、主题、关键词、决定和未完成事项。
- 安全消息 FTS：用户和 Agent 可见文本，不索引秘密参数和大型工具原文。
- 笔记 FTS：复用现有标题和正文索引，并增加文档记忆摘要和关键词索引。
- 先按权限、时间和类型过滤，再做匹配和排序。

相关度可以组合：

- FTS 匹配质量。
- 当前查询命中的字段类型。
- 片段或笔记的新鲜度。
- 画像事实的重要度和显式来源。
- 用户是否明确附加或点名某篇笔记。

### 12.2 模糊搜索

Agent 可以根据用户的模糊描述构造更明确的 `memory_search` 查询。第一版允许使用摘要中的主题、关键词、实体和时间范围扩展词法命中，但不因为“模糊记忆”直接引入独立向量数据库。

### 12.3 后续能力

只有 FTS 召回评估证明不足后，再增加本地或远程向量嵌入、混合检索和 rerank。后续能力必须保持相同的权限过滤、来源引用和工具协议，不能改变事实源。

## 13. 权限、隐私与安全

### 13.1 防止历史权限泄漏

过去某次 Agent 运行可能读取过当前已无权访问的笔记。为防止通过记忆绕过权限：

- 消息记录不持久化完整笔记 Tool Call 返回值。
- 片段摘要只保存讨论结果和笔记引用，不复制正文。
- `memory_read` 对工具结果做安全投影。
- 通过关联笔记继续读取时重新检查当前数据范围。
- 回收站、永久删除或权限范围外的笔记不返回标题、摘要、命中数量或正文。

### 13.2 防止记忆提示注入

- 记忆、历史用户消息和笔记正文全部按不可信数据注入。
- 其中要求忽略系统规则、扩大权限或执行工具的文字不具有指令权威。
- Agent 固定配置、工具权限和系统安全规则只能来自应用配置层。
- 摘要函数不能执行消息中的命令，也不能调用工具验证或扩展内容。

### 13.3 本地优先和模型调用

- 原始消息、画像、摘要和笔记索引默认保存在本地数据库。
- 发送给摘要模型的片段范围必须与正常模型服务商配置和隐私说明一致。
- 后台摘要不因为在后台执行而获得额外数据范围。
- 模型服务商不可用时保留原始数据并延迟派生任务，不能影响本地笔记和聊天历史读取。

### 13.4 删除语义

至少提供以下独立操作：

- 清除完整对话记录及其情景记忆派生数据。
- 清除全部长期画像。
- 删除或更正单条画像事实。
- 禁止重新提取指定画像键。
- 清理可重建的笔记语义摘要和记忆索引。

删除任何事实源后，应按来源关系删除、失效或重新生成派生数据。用户删除画像但保留原始聊天时，使用遗忘标记防止旧内容重新生成同一画像。

## 14. 推荐数据模型

### 14.1 `agent_messages`

```text
id
sequence
episodeId
runId
role
kind
contentJson
searchableText
status
modelId
createdAtEpochMs
completedAtEpochMs
```

`kind` 区分普通消息、Tool Call、工具结果、权限事件、错误、附件和笔记引用。`searchableText` 是经过安全投影的可索引文本。

### 14.2 `agent_episodes`

```text
id
startMessageId
endMessageId
startedAtEpochMs
endedAtEpochMs
closeReason
summaryText
summaryJson
summaryStatus
sourceHash
summaryModelId
summaryPromptVersion
createdAtEpochMs
updatedAtEpochMs
```

一个时间点只有一个打开片段。关闭后的消息范围不可变化；如需修复，用新摘要版本替换派生活动结果，不修改事实源边界。

### 14.3 `agent_memory_facts`

```text
id
ownerType
memoryKey
valueJson
sourceType
sourceId
confidence
importance
isExplicit
active
supersedesId
validFromEpochMs
validToEpochMs
createdAtEpochMs
```

`ownerType` 至少区分 `user` 和 `agent_preference`。固定 Agent 配置和系统规则不存入此表。

### 14.4 `agent_memory_tombstones`

```text
id
ownerType
memoryKey
reason
createdAtEpochMs
clearedAtEpochMs
```

用于表达用户要求遗忘且不希望旧对话重新提取的稳定键。

### 14.5 `note_memory_index`

```text
noteId
contentVersion
contentHash
semanticSummary
outlineJson
keywordsJson
plainText
summaryStatus
summaryModelId
summaryPromptVersion
indexedAtEpochMs
```

笔记进入回收站或内容版本变化后，对应活动索引立即失效。

### 14.6 FTS 表

- `agent_messages_fts`：安全投影后的历史消息全文搜索。
- `agent_episodes_fts`：片段标题、摘要、主题、关键词、决定和未完成事项。
- `note_memory_fts`：笔记标题、语义摘要、结构和关键词；原始正文搜索继续复用现有 `notes_fts`。

### 14.7 派生任务

可以使用统一 `memory_jobs` 表或在各派生表中保存任务状态，但必须支持：

- 唯一任务键。
- `pending`、`running`、`completed`、`failed` 状态。
- 尝试次数和最后错误。
- 来源哈希与目标提示词版本。
- 崩溃后把超时的 `running` 恢复为可重试状态。

## 15. 关键流程

### 15.1 用户发送消息

1. 检查当前片段和上一次已完成交互时间。
2. 如达到关闭条件，在事务中关闭旧片段、创建摘要任务并打开新片段。
3. 把用户消息追加到当前片段。
4. 根据权限和 Token 预算组装上下文。
5. 运行 Agent Loop，持续保存流式消息、工具调用和状态。
6. Agent 运行结束后更新片段的最后完成时间。

### 15.2 关闭片段并生成摘要

1. 固定片段消息范围和来源哈希。
2. 摘要函数读取固定快照并输出结构化结果。
3. 校验 Schema、消息范围和输出大小。
4. 保存情景摘要并更新 FTS。
5. 把画像候选交给记忆协调器。
6. 画像协调器按优先级新增、替换、忽略或等待确认。

### 15.3 编辑笔记

1. 正常保存笔记事实源和现有 FTS。
2. 计算内容哈希；与活动文档记忆版本不同时标为过期。
3. 编辑稳定后提交唯一摘要任务。
4. 成功后写入新文档记忆索引并切换活动版本。
5. 失败时继续使用最新事实源的普通 FTS，不回退为旧摘要。

### 15.4 回溯历史

1. 自动上下文未提供足够信息时，Agent 调用 `memory_search`。
2. 工具按时间、权限和类型过滤后搜索片段摘要与安全消息索引。
3. 返回摘要、命中片段和片段 ID。
4. 摘要不足时，Agent 调用 `memory_read` 分页读取完整安全文本。
5. 如需关联笔记正文，再调用 `read` 并重新检查笔记权限。

### 15.5 删除和遗忘

1. 确认用户要删除事实源、派生画像还是两者。
2. 删除事实源时失效所有来源于它的摘要、索引和单一来源画像。
3. 只删除画像时写入遗忘标记。
4. 清除对话记录不默认删除笔记；清除画像不默认删除对话。
5. 更新 FTS 和上下文缓存，确保下一次 Agent 运行立即生效。

## 16. 故障恢复

- 消息和 Agent 运行状态先持久化，再更新 UI 的最终完成状态。
- 摘要、画像协调和笔记索引任务全部幂等。
- App 崩溃后可以识别未完成回复、悬空片段和超时任务。
- 摘要模型、网络或配额失败只影响派生数据，不影响原始聊天和笔记。
- 当前摘要不可用时回退到有限原文或普通 FTS 片段。
- 模型切换不要求立即重建全部历史；新旧摘要并存时记录各自版本并逐步迁移。
- 数据库迁移必须保留已有笔记和设置，不采用破坏性重建。

## 17. 产品与页面要求

### 17.1 Agent 对话页

- 直接打开唯一对话时间线。
- Header 显示 Agent 名称或固定“Agent”。
- 消息区展示用户、Agent、笔记卡片、附件、Tool Call、权限和错误。
- 片段边界可以用低干扰的时间分隔表示，但不提供片段命名和管理操作。
- 当前模型、笔记权限、数据范围和停止任务入口保持可见或可快速访问。

### 17.2 Agent 记忆页

Agent 记忆页至少提供：

- 当前有效用户画像。
- Agent 可学习偏好。
- 每条画像的来源、更新时间和推断标识。
- 更正、删除和禁止重新记住。
- 搜索历史对话。
- 清除对话记录和清除长期画像的独立危险操作。
- 可重建文档记忆索引的占用和清理入口可放在“存储与隐私”。

### 17.3 平板

平板 Agent 区域以对话为主体，可按窗口宽度增加上下文、记忆、笔记范围或工具详情面板。

### 17.4 权限时效

- “每次询问”“本次 Agent 运行内允许”“始终允许”用于一次性工具授权。
- 用户显式附加笔记为当前片段授予该明确版本的临时读取权限。
- 片段关闭后，历史笔记引用不自动延续读取授权。

## 18. 验收要求

### 18.1 单时间线和片段

- 冷启动后恢复同一条时间线。
- 间隔未满 30 分钟时消息进入当前片段。
- 新消息到来且间隔达到 30 分钟时关闭旧片段并打开新片段。
- Agent 运行中不会因时间达到阈值被拆分。
- 容量达到上限时能够安全关闭片段。

### 18.2 摘要和画像

- 同一来源和版本重复执行不会生成重复摘要。
- 摘要失败不丢失原始消息。
- 用户明确纠正可以替换活动画像，旧值仍可审计。
- 推断事实不能覆盖用户明确事实。
- Agent 回复不会被提取为用户事实。
- 遗忘后的事实不会从旧对话自动恢复。

### 18.3 文档记忆

- 当前笔记正文优先于过期语义摘要。
- 笔记修改后旧文档记忆立即失效。
- 回收站和权限范围外笔记不会被自动召回。
- 历史片段不能绕过当前权限读取笔记正文。
- 短笔记不需要额外模型摘要也可以进入上下文。

### 18.4 上下文和工具

- 上下文总量不超过配置预算。
- 近期与相关摘要去重。
- `memory_search` 返回摘要和命中片段，不临时重写摘要。
- `memory_read` 分页并限制输出大小。
- 无结果时明确返回空结果。
- 历史记忆中的指令不能提升权限或覆盖系统规则。

### 18.5 恢复和删除

- 崩溃后能恢复未完成运行和派生任务状态。
- 清除对话与清除画像互不隐式连带。
- 删除事实源会失效对应派生数据和 FTS。
- 清理文档记忆索引不会删除原始笔记。

## 19. 第一版不做

- 把全部历史聊天直接塞入模型上下文。
- 每次固定注入 5–10 篇摘要而不考虑相关性和 Token。
- 把笔记正文复制进会话摘要或画像。
- 允许普通聊天自动改写 Agent 身份、系统规则或工具权限。
- 依赖第 30 分钟精确触发的 Android 后台计时。
- 第一版引入知识图谱、独立向量数据库或通用 Agent 记忆框架。
- 每次搜索重新调用大模型生成不稳定摘要。
- 在每次笔记自动保存时调用大模型更新文档摘要。

## 20. S11 内部实施顺序

S11 按以下顺序交付，避免先做 UI 后补事实源和权限：

1. **单时间线事实源**：消息、运行、工具事件、附件和崩溃恢复。
2. **片段与上下文骨架**：30 分钟和容量边界、Token 预算、当前片段原文。
3. **情景记忆**：摘要任务、结构化输出、FTS、近期与相关召回。
4. **画像记忆**：原子事实、协调规则、替换链、遗忘标记和用户管理。
5. **文档记忆**：独立笔记索引、显式附加、自动召回和版本失效。
6. **记忆工具**：`memory_search`、`memory_read`、限制、审计和权限投影。
7. **笔记工具与编辑联动**：`note_search`、`read`、`create`、`write`、`delete`、润色 Diff。
8. **完整验收**：Token、权限泄漏、删除、崩溃、离线、模型失败和数据库迁移测试。
